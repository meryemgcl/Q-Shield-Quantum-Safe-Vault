# Security Policy

## Supported Versions

| Version | Supported          | Security Status |
| ------- | ------------------ | --------------- |
| 1.0.x   | :white_check_mark: | Active (NIST FIPS 203 / 204 Compliant) |
| < 1.0   | :x:                | Deprecated |

## Reporting a Vulnerability

We take the security of **Q-Shield** very seriously. If you discover a cryptographic vulnerability, side-channel leak, or implementation bug, please follow these steps:

1. **Do NOT open a public GitHub issue.**
2. Email your findings directly to **lifevern@gmail.com** with the subject line:
   `[SECURITY] Q-Shield Vulnerability Report`.
3. Provide:
   - A detailed description of the attack vector (e.g., Timing attack, Fault injection, Replay, OOM).
   - Minimal reproducible proof-of-concept (PoC) code or script.
   - Any proposed remediation or patches.

### Response SLA
- **Initial Response:** Within 24 hours.
- **Triage & Validation:** Within 72 hours.
- **Coordinated Disclosure & Patch:** Within 14 business days.
